## Turn 3 — User: "i think it was because of the mem leak"
**Assistant** (after capped re-tests): not a classic leak — Firefox retains
each reloaded ~1 GB engine instance (256 MB wasm heap + compiled code for
the 89 MB module) and reclaims LAZILY (~30-60 s+). Rapid reloads stack
instances unboundedly (4 GB after 3 quick reloads); spaced reloads stay
bounded (~2.4 GB peak); Chromium tears down within a cycle or two. An
unload/pagehide bfcache-block did NOT change it (bfcache wasn't the
mechanism — old no-store-document tests ratcheted identically). Playwright's
ephemeral Firefox profile has no HTTP cache, so 304 wins don't show in that
harness, but real profiles benefit. Conclusion: lockup = reload stacking +
no-store recompile spikes on 2 GB swap. Commit **8b46572**; gates re-run
green.

### The abort family, root-caused one layer at a time
1. **WorkQueue thread-spawn abort**: every WorkQueue::create spawned a
   real thread (pthread_create=ENOTSUP → Thread::create RELEASE_ASSERT →
   abort()); first <img> died in ImageFrameWorkQueue. PATCH:
   WorkQueueGeneric backs ALL queues with the main RunLoop; dispatchSync
   inline; ConcurrentWorkQueue::apply serial. → data: images decoded.
2. **loadsImagesAutomatically defaults FALSE** in raw WebCore (root cause
   #8): network images silently deferred — no request, no error, blank
   <img>. FIX: one line in main.cpp settings. → gate5 3/3.
3. **ImageFrameWorkQueue spin-deadlock**: SynchronizedFixedQueue
   (BufferSize=8) blocking enqueue can't be satisfied by another thread —
   Wikipedia (>8 pending decodes) spun the only thread at 100% CPU
   forever. PATCH: dispatch() decodes via callOnMainThread, no fixed
   queue. → **Wikipedia Main Page renders WITH images** (logo, featured-
   article photo). Lesson: blocking primitives NEVER work on the only
   thread — wasm futex waits spin hot.
4. User: "google.com also aborts, ebay.com aborts any site with anything
   relatively complex likes to abort" + pasted a 2captcha abort log.
   Diagnosis via temp `-sASSERTIONS=1` + `--profiling-funcs` (symbolized
   pageerror stacks in tools/site-diagnose.mjs — both flags REVERTED
   after): **root cause #9 — our own createBlobRegistry() nullptr stub**;
   first `new Blob()` any modern bundle runs → blobRegistry() CheckedRef
   null → abort. google/ebay/Turnstile all died there. FIX:
   EmbedderBlobRegistry forwarding to in-process BlobRegistryImpl
   (WebKitLegacy pattern) + blob: loads via loader.start()
   (BlobResourceHandle builtin map).
5. **Worker::create** now throws NotSupportedError (catchable) instead of
   aborting (Turnstile et al. use workers). SharedWorker settings-gated
   off already.
6. **In-page WebSocket**: CurlStreamScheduler got the main-thread pump
   (CurlRequestScheduler recipe), and CurlStream FAILS streams immediately
   — its blocking CONNECT_ONLY perform can never complete single-threaded
   (SOCKFS WebSocket needs the starved JS loop). Pages get clean error
   events; real WS = deferred multi-interface rework.

RESULTS: google, ebay, 2captcha **no longer abort**. eBay homepage renders
(hero, logos, search UI, 23 wisp streams). old.reddit = engine-correct,
server bot-block page (cookies needed). Benign leftover: "missingImage"
