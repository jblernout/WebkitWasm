### Investigation
- CurlRequestScheduler runs a worker thread parked in blocking
  poll(INT_MAX) — impossible single-threaded, but the loop body is
  pumpable. Decision: main-thread RunLoop pump (libcurl.js precedent),
  NO pthread rebuild (would mean rebuilding the whole wasm-sysroot tier).
- curl ResourceHandle DOES NOT EXIST in 2.52 — `ResourceHandle::start()`
  is ASSERT_NOT_REACHED on USE(CURL). The LoaderStrategy must intercept
  loads and feed ResourceLoader via its public WK2-style interface
  (didReceiveResponse + policy completion, didReceiveBuffer,
  didFinishLoading, didFail). NetworkDataTaskCurl studied as reference.
- All curl WebCore sources were ALREADY compiled (platform/Curl.cmake);
  missing symbols only surface when the loader references curl objects

### Root causes fought (all silent; #4–#7 of the empty-client family)
4. EmptyFrameLoaderClient dispatchDecidePolicyFor* DROP the
   FramePolicyFunction → navigations stall forever (caught BEFORE first
   run by reading EmptyClients.cpp).
5. canShowMIMEType() == false → content policy rejects every response.
6. committedLoad() empty → bytes never reach the parser.
7. canHandleRequest() == false → PolicyChecker refuses every URL.
Plus the killer config trap: ENABLE_FTPDIR=ON → CurlHandle passes
"file,ftp,ftps,http,https" to CURLOPT_PROTOCOLS_STR; curl's
protocol2num() ZEROES the allowlist then fails mid-parse at unbuilt
"ftp" → only "file" allowed → every http(s) load died
CURLE_UNSUPPORTED_PROTOCOL ("Protocol \"http\" disabled" — found via a
temporary error-buffer probe; the generic strerror was useless; a
standalone emcc probe proved the .a itself was fine).
Note: WEBKIT_OPTION_DEFAULT_PORT_VALUE only affects FRESH caches —
existing build dir needed one-time -DENABLE_FTPDIR=OFF.
Also: ninja wide rebuilds can OOM-kill em++ SILENTLY (FAILED block shows
only warnings) — re-run ninja.
