# Building BrowserInBrowser

End-to-end: recreate the engine tree, build the wasm engine, serve it, open it.
Linux host. First build is long (WebKit + ~16 wasm deps + WebCore); rebuilds are
incremental.

## 0. Host prerequisites

```bash
sudo apt install -y build-essential cmake ninja-build pkg-config \
                    git curl tar xz-utils unzip python3
# node (18+) for the dev + Wisp servers:
#   https://nodejs.org  (or nvm)
```

`bootstrap.sh` checks for all of these and stops early if any are missing.

## 1. Bootstrap the engine tree (`third_party/`)

A clone has none of the engine (it's gitignored, ~11 GB). Recreate it:

```bash
bash tools/bootstrap.sh
```

This clones the pinned WebKit (`webkitglib/2.52 @ aec9d2ad95`), applies
`src/patches/webkit-emscripten.patch`, installs Emscripten 6.0.0, and builds the
wasm dependency tier into `third_party/wasm-sysroot` in the required order
(**icu → webcore-deps → curl-tier**). Pins: `docs/summaries/decision-002-toolchain-pins.md`.

- **Time / disk:** ~30-90 min, ~15 GB. Idempotent — re-run to resume after an
  interruption (each dep skips if already installed).
- `npm install` once too, for the dev/Wisp servers (`@mercuryworkshop/wisp-js`).

## 2. Build the engine

```bash
bash tools/build-webcore.sh                 # main branch: pthread GPU
# or, on the non-pthread branch (or to force it):
BIB_PTHREAD=0 bash tools/build-webcore.sh   # main-thread GPU
```

Output: `build/webcore/bin/embedder.{js,wasm}` (+ `bib-build-config.js` stamping
the threading mode the host page reads).

- **RAM:** WebCore's unified TUs need ~1.2 GB+ clang RSS each. Cap parallelism
  with `BIB_JOBS` — `BIB_JOBS=4 bash tools/build-webcore.sh` (~5 GB peak) is safe
  on a 16 GB box; the default (`nproc`) can fill RAM and stall. Don't keep heavy
  browser tabs (107 MB wasm each) open during the build.
- **Resumable:** ninja is incremental; a killed build picks up where it stopped.
- Flipping `BIB_PTHREAD` changes compile flags → recompiles the whole tree
  (~1.5-2 h). Use a separate build dir per mode if you toggle often.

## 3. Serve it

Two servers, both required:

```bash
npm run wisp &                                                    # Wisp: 127.0.0.1:5001
node tools/dev-server.mjs web --mount /engine=build/webcore/bin   # page: 127.0.0.1:8080
```

The dev server sends **COOP `same-origin` + COEP `require-corp`** (needed for
SharedArrayBuffer/pthreads). The Wisp server tunnels all engine network traffic.

## 4. Open

```
http://localhost:8080/browser.html?url=https://example.com
```

Hard-reload (Ctrl+Shift+R) after a rebuild — the 107 MB wasm caches aggressively.

Useful URL params: `?rcap=0` disables the render throttle (max MotionMark, may
stutter on heavy pages); `?rcap=N` pins it; absent = dynamic. `?gpu=0` forces
raster.

## 5. Optional: verify

```bash
node tools/gate2-browser-test.mjs   # raster paint gate
node tools/gate8-gpu-test.mjs       # GPU present gate
```

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `curl=7 Could not connect` on every site | Wisp server not running. `npm run wisp &` |
| Build fills RAM / stalls | Lower `BIB_JOBS` (try 3-4). |
| `bootstrap` patch step says "already applied" | Fine — the patch is in the tree. To redo: `git -C third_party/WebKit reset --hard <pin> && git -C third_party/WebKit clean -fd` then re-run bootstrap. |
| Page blank / wrong present mode | Check `bib-build-config.js` was regenerated by the build and is served from `/engine/`. Hard-reload. |
| `port 8080 in use` | A previous dev server is still up. Find it: `pgrep -af 'tools/[d]ev-server'`, kill by PID. (Don't `pkill -f dev-server.mjs` from a shell whose own command contains that string — it kills itself.) |
| pthread engine won't load (`SharedArrayBuffer is not defined`) | Host isn't sending COOP/COEP. Use `tools/dev-server.mjs`, or build the `non-pthread` branch. |
